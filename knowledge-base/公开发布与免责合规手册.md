# 公开发布与免责合规手册

> 适用：把本技能包（或任何求职类内容）发到 GitHub／知乎／公众号等公开渠道**之前**的合规叠甲，以及**之后**被投诉、发现失实时的处理  
> 核心原则：只解决信息不对称，不指代真实主体，不提供造假与攻击手段；**能核实的事实才写，核实不到的写"未查到"**，一条边界不清的内容比少一条内容更贵  
> 来源：本手册所有条号于 **2026-10-22** 联网核实，来源清单见第十节；核实不到的一律标注"未查到，发布前用 flk.npc.gov.cn 或 12348 复核"。**本手册不构成法律意见**，示例均为虚构（XX 公司、张三），不指向任何真实企业、个人或律所个案。

## 一、免责与立场声明：怎么写才有效，怎么写没用

| 写法 | 有没有用 | 为什么 |
|------|---------|--------|
| 顶部引用块 + 文末各放一份"本文不构成法律意见" | ✅ 有效 | 显眼位置才能证明读者是被提示过的；只放文末容易被判"未充分提示" |
| 写明"所有公司与人名均为虚构（XX 公司、张三），不指向任何真实主体" | ✅ 最有效 | 直接把名誉权/商誉侵权的"指向特定主体"要件拆掉 |
| 写明立场：不教造假、不教隐瞒、判据是什么 | ✅ 有效 | 证明发布目的正当，影响平台与监管对内容的定性 |
| 给每个数字／条号附来源机构＋日期＋URL | ✅ 有效 | 这是《民法典》第 1025 条"合理核实义务"最实在的证据（见第二节） |
| 写明"内容有失效可能，以现行规定为准，欢迎提 issue 指正" | ✅ 有效 | 法律会变；这是失实后的减责依据 |
| "本人不承担任何责任""转载后果自负" | ⚠️ 有限 | 单方免除自身责任的表述不改变行为本身的定性，不能替代内容合规 |
| "本文仅供学习参考"然后继续写攻击方法 | ❌ 无效 | **声明不能免除故意传播虚假信息的责任**：第 1025 条把"捏造、歪曲事实"明确列为不免责情形；加声明只是说明你知情，甚至可能被认定为明知而为之 |

**可直接抄的声明块**（放在每份公开文档顶部，本仓库多数文档已具备，缺的要补）：

```
> ⚠️ 本文不构成法律意见，仅用于帮助你理解处境、准备问题清单。
> 示例公司与人名一律虚构（XX 公司、张三、李四），不指向任何真实企业或个人。
> 法规与数字截至 20XX-XX-XX 核实，可能已变化，以官方现行文本为准；发现内容失实请开 issue，核实后 7 日内更正或下架。
```

## 二、名誉权与商誉边界（发求职内容最容易踩的一块）

| 条文 | 内容要点 | 对写作者的意义 |
|------|---------|--------------|
| 《民法典》第 1024 条 | 民事主体享有名誉权，任何组织或个人不得以**侮辱、诽谤**等方式侵害；名誉是对品德、声望、才能、信用等的社会评价 | 只要内容能被识别到"某家具体公司"，就有侵害空间 |
| 《民法典》第 1025 条 | 为公共利益实施新闻报道、**舆论监督**等影响他人名誉的，**不承担民事责任**，但三种情形除外：①捏造、歪曲事实；②对他人提供的严重失实内容未尽到合理核实义务；③使用侮辱性言辞等贬损他人名誉 | 这是求职者发声的**主要合法性依据**：写"客观事实＋合理核实"落在保护内；写"定性结论＋情绪化辱骂"落在除外情形里 |
| 《民法典》第 1026 条 | 判断是否尽到合理核实义务，考虑内容来源可信度、对明显可能引发争议的内容是否进行必要调查等因素 | 来源可溯（公告文书、年报、官方通报、多平台交叉印证）＝尽职；"听说的""群里说的"＝未尽职 |

**三层写法：同一段经历，怎么写站得住**

| 层 | 例子（张三／XX 公司） | 结论 |
|----|---------------------|------|
| 可核实事实 | "JD 标注 15K，offer 给 11K，签约主体与面试公司名不一致" | ✅ 写，附证据（截图时间线、公告信息） |
| 主观结论 | "面试流程信息透明度低，我据此判断沟通成本偏高" | ⚠️ 写但必须显式标注为"我的判断"，并紧跟事实依据 |
| 情绪化定性 | "骗子""黑厂""压榨员工""这家就是垃圾" | ❌ 不写。属第 1024 条侮辱/诽谤风险，且落入 1025 条除外情形 |

**为什么本仓库一律用 XX 公司、不给真实公司下定性结论**：一旦给出"骗子/黑厂"这类定性，举证责任实质上落到发布者身上，而读者传播时只会保留结论不保留事实——你为一句情绪词要付出的是完整核实成本＋诉累。要提醒"某类公司高风险"，写成**类型化红旗清单**（成立不足 1 年且无融资、参保人数与团队规模严重不符、大量劳动争议记录等），让读者自己去查具体主体，结论由读者基于公开数据形成。

**对个人 vs 对经营者，适用规则不同**：

| 对象 | 主要适用 | 差别 |
|------|---------|------|
| 前雇主／HR 个人 | 《民法典》第 1024 条名誉权 + 个人信息保护（见第四节） | 对**具体个人**（面试官、HR、前同事）的点名评价风险更高，还可能同时触碰隐私与个人信息；一律匿名化 |
| 作为经营者的公司 | 《民法典》第 1024 条（法人名誉／商誉）为主 | 求职者点评前雇主，通常**自己不是"经营者"**，也不与公司存在竞争关系 |
| 商业诋毁 | 《反不正当竞争法》（2025 年修订，2025-10-15 施行）**第十二条**：经营者不得编造、传播或者指使他人编造、传播虚假信息或者误导性信息，损害其他经营者的商业信誉、商品声誉 | 2025 年修订两处收紧：对象由"竞争对手"扩为"**其他经营者**"，并明确把"**指使他人**编造、传播"列为行为方式。普通劳动者一般不落入"经营者"要件，但**替你转发、带节奏的人**可能构成被指使者——这是"不要组织他人去刷差评"的法律理由 |

## 三、商业秘密与保密／竞业义务：内部资料一律不发

| 禁止发布 | 依据／风险 |
|---------|-----------|
| 从在职或离职单位带出的内部文档、设计稿、代码片段、数据库导出、客户名单、报价单、组织架构截图、内网截图、飞书/企微聊天记录截图 | 《反不正当竞争法》（2025 年修订）**第十条**列举的侵犯商业秘密行为，含"以盗窃、贿赂、欺诈、胁迫、**电子侵入**或者其他不正当手段获取权利人的商业秘密"；即使你有权访问，披露仍可能违反劳动合同**保密条款**与竞业限制义务 |
| 未公开的经营数字（营收、毛利、用户量、融资条款、裁员名单） | 属"经营信息"典型候选；一旦公司主张并已采取保密措施，举证与赔偿压力在你 |
| 面试中对方透露的内部技术方案、未发布产品细节 | 即便口头获得，公开披露仍可能引发违反保密约定／诚信义务争议 |

商业秘密通说需同时满足：**不为公众所知悉、具有商业价值、权利人已采取相应保密措施**（该定义条款截至 2026-10-22 未逐字核实条号，发布前用 flk.npc.gov.cn 复核现行文本）。

**"我知道的经验" vs "公司未公开的信息"，怎么写分界**：

1. **公开渠道可复现吗？** JD、官网、上市公告、招股书、公开论文/技术博客、应用商店里能查到的 → 可写；只有内部才有的 → 不写。
2. **写方法不写载体**：写"我如何做性能归因（分层评测、召回率/延迟拆解）"，不贴内部代码与截图；把公司专有的业务参数、数据集规模换成占位符或区间。
3. **写结论不写原料**：写"这类合同常见把加班费并入月薪的条款，签字前要问清"，不上传真实合同 PDF。
4. **不确定就不发**：涉及竞业限制期内原单位的岗位／项目描述，改成类型化描述（"某新能源车企的车机团队"）或完全不写；竞业期内额外收口，不发任何可能被认为"利用原单位未公开信息"的内容，避免被主张违约（《劳动合同法》关于保密约定与竞业限制义务的规定；条号截至 2026-10-22 未逐字复核，以现行文本为准）。

## 四、个人信息保护：别人的一律不进公开库

| 材料 | 为什么是个人信息 | 发布前处理 |
|------|----------------|-----------|
| 同事／HR／面试官姓名、工牌、部门＋入职时间组合 | 可识别到特定自然人 | 改为"张经理""HR 李四"等**虚构称谓**，不要只打码 |
| 群聊／私聊截图 | 含昵称、头像、时间戳、说话人身份 | **不上传**；改写成虚构对话稿（本仓库全部示例采用此法） |
| 工资单、社保记录、offer、离职证明截图 | 含姓名、身份证号、公司、金额 | 不上传真实件；用纯文本表格 + 虚构数字（XX 公司／张三／税前 10000） |
| 同事绩效评价、他人对你的评价 | 第三方个人信息 + 名誉交叉 | 匿名化到不可复原，或只写抽象结论 |
| **git 提交里的作者名与邮箱** | 不在文件内容里，但每条提交都携带，push 之后**永久公开**且可被爬虫抓取（`%an`/`%ae` 与 GitHub API 都能读） | 发布前给**这个仓库**单独设对外身份（不加 `--global`），用 GitHub 提供的 `用户ID+用户名@users.noreply.github.com` 或一个不挂个人联系方式的昵称；提交尚未 push 时可直接重做，改成本最低 |

- **同意原则**：《个人信息保护法》第十三条把"取得个人的同意"列为处理个人信息的合法情形之首；第十四条要求同意"由个人在充分知情的前提下自愿、明确作出"，处理目的、方式或信息种类变更应重新取得同意。**向不特定公众公开发布，几乎不可能拿到同事与前雇主的这种同意**——所以正确做法不是打码，而是**改写成虚构案例**。
- **打码为什么不够**：图片元数据（EXIF 里机型、时间、有时含路径）、上下文可拼出身份（"2024 年 3 月入职 XX 部门做支付的后端"）、码没盖住的头像/群名，都能被复原。
- **个人记忆库不进公开仓库**：真实简历、职业时间线、逐份 offer 分析属个人数据。本仓库 `.gitignore` 第 3 行已忽略 `/memory/`，README 也写明"公开去隐私版"——发布前必须复核这条忽略仍在生效（见第九节命令）。
- **交给第三方 AI 也算"提供给他人处理"**：把简历、合同、花名册、内部截图粘进任何在线模型，等于把可识别信息送出你的控制范围，且事后无法收回。同表处理方式一样——**先删先换再问**：删自己的证件号与住址，把别人的姓名换成角色称谓、公司换成 XX 公司，只贴需要判断的那一条条款。本仓库已把这条写进《AI辅助求职实操教程》的"用 AI 之前"一节与 jd-analysis-and-resume-tailoring、contract-reviewer 的禁止行为。

## 五、著作权与开源许可：别人写的要署名，自己写的要授权

| 情形 | 后果／要求 |
|------|-----------|
| 引用他人 skill、文章、教程 | 保留署名与原许可证声明，标注"改写自××"的范围；本仓库 README 已有"借鉴来源与致谢"表（每条附真实仓库 URL + 许可证），维持这一做法并逐条复核链接 |
| **MIT** | 允许商用、修改、再分发；**要求保留版权与许可声明**；**不含明示专利授权**（choosealicense.com 的许可证对照） |
| **Apache-2.0** | 同 MIT 的自由度，另有：需保留 NOTICE/声明、修改后需标注变更；**第 3 条含明示专利授权，并附专利报复条款**（你对贡献者提起相关专利诉讼则其专利授权终止）。技术类仓库若担心专利争议，Apache-2.0 比 MIT 更稳 |
| 仓库**没有 LICENSE** | 默认"**保留所有权利**"：他人复制、修改、分发你的内容在法律上未获授权（choosealicense.com：无许可即无授权）；反过来你也难以正当主张"别人可以随便用我的 skill"。GitHub 首页会显示"no license"，公开传播的技术包建议**必须**补一个 LICENSE 文件 |
| 把别人仓库 clone 下来改名当自己的发布 | 侵犯复制权／署名权／信息网络传播权，属可被投诉下架并索赔的行为；衍生发布必须保留原作者许可与署名，并写清你改了什么 |

**最小动作**：根目录加 `LICENSE`（MIT 或 Apache-2.0 二选一，与本仓库已借鉴的上游许可证兼容为准）→ 在 README"借鉴来源与致谢"列出所有第三方与其许可证 → 对每个借鉴条目保留原始 URL。

## 六、取证类内容的合法性边界（本仓库有大量取证建议，必须同页写清）

**证据合法性口径**：《最高人民法院关于适用〈中华人民共和国民事诉讼法〉的解释》（2022 年修正）**第一百零六条**——对以**严重侵害他人合法权益**、**违反法律禁止性规定**或者**严重违背公序良俗**的方法形成或者获取的证据，**不得作为认定案件事实的根据**。司法实践对"是否严重侵害"的把握，通常区分"偷录自己参与的对话"与"侵入他人私密空间的窃听"（法院公开文章多有讨论，如范县法院网《录音证据认定的 10 个裁判观点》，2022-11-02）。

| ✅ 可以做 | 🚫 不能做 |
|----------|----------|
| 录**你自己参与**的谈话（离职沟通、辞退谈话、绩效面谈），全程连续不剪辑、当天记录时间与在场人 | 窃听他人之间的对话、在他人工位/会议室/私密空间放设备 |
| 保留自己账号下的聊天记录、邮件、自己签署的文件、工资流水、社保缴费记录 | 侵入他人邮箱／内网／数据库取数，盗用他人账号，伪造授权 |
| 要求对方出具书面材料（离职证明、解除通知）并留存 | 以曝光、举报相要挟索取利益（可能另涉敲诈勒索风险，具体构成要件截至 2026-10-22 未逐字核实） |
| 客观记下同意的过程，必要时告知"我在录音" | **诱导对方作出陈述**（设套提问、替对方"补台词"、反复暗示期望答案）——这类内容证明力低且属不正当取证 |

**红线：不得伪造、毁灭证据，不得虚假诉讼**

| 行为 | 后果（条号已核实） |
|------|------------------|
| 伪造、毁灭重要证据，妨碍法院审理 | 《民事诉讼法》（2023 年修正）**第一百一十四条**：可予**罚款、拘留**；构成犯罪的依法追究刑事责任 |
| 以捏造的事实提起民事诉讼；指使他人作伪证、帮助当事人毁灭／伪造证据 | 《刑法》**第三百零七条之一**虚假诉讼罪（三年以下有期徒刑、拘役或管制，并处或单处罚金；情节严重三至七年）；《刑法》**第三百零七条**（妨害作证罪、帮助毁灭、伪造证据罪） |
| 伪造离职证明／Offer 上的公司**印章** | 《刑法》**第二百八十条第二款**伪造公司、企业、事业单位、人民团体印章罪：处三年以下有期徒刑、拘役、管制或者剥夺政治权利，并处罚金 |

**发布角度的要求**：写"可以录音留证"时，**必须同段写边界**（只录自己参与的、不得窃听、不得诱导、不得剪辑）。只写"全程录音"而不写边界，等于教人越界，既误导读者也放大发布者的道义与舆论风险。本仓库《离职与背调合规手册》已写明"不要以假制假（伪造好评截图、伪造在职证明、找人冒充上级接电话）"，这一句是正面范例，公开版应保留。

## 七、不能提供的建议类型（价值观红线，沿用仓库既有判据）

**判据**（已确立，见《职场小技巧与人情世故》开头与 README）：**当着当事人／对方的面，把这条做法说出来，你还愿不愿意承认。** 愿意＝正当自我保护；不愿意＝心机或违法，不写。

| 不写 | 为什么 | 改写成什么 |
|------|-------|-----------|
| 虚报薪资、编造 offer 与竞对报价 | 属虚假陈述，背调必穿帮；且可能构成欺诈性谈判 | "统一真实口径"：用真实结构（总包、绩效、公积金比例）横向比价 |
| 伪造离职证明、在职证明、收入流水、公司印章；虚假诉讼、伪造或删改聊天记录、找人冒充上级接电话 | 印章类直接触刑；伪造证据与虚假诉讼可罚款、拘留直至刑责（见第六节表） | 教合法替代路径：向原单位主张法定四项离职证明、向社保／公积金记录取数；只做真实留痕（导出记录、保全时间戳、书面确认） |

## 八、被投诉、被要求删除、发现内容失实时怎么办

| 步骤 | 动作 | 注意 |
|------|------|------|
| 1. 登记不删除 | 先把投诉原文、时间、渠道留档，开 issue 标记 `needs-verification` | 未核实前**不公开**投诉人姓名、公司、聊天截图（这一步最容易二次侵权） |
| 2. 判定性质 | 失实（事实错）／未核实（来源不足）／侮辱性表述（措辞越界）／指向真实主体 | 只有"措辞正当但结论不利"才是可保留的正当舆论监督 |
| 3. 更正 | 事实错误：直接改文并在文件顶部加更正说明；数字时效过期：更新核实日期与来源 | 模板：`> 更正（20XX-XX-XX）：原第 X 节"……"表述不准确／依据不足，已修改为"……"。感谢指出。` |
| 4. 下架 | 无法核实来源、含他人个人信息、含内部资料 → 删除该段并在 git 提交信息里留一行记录 | 删除要留痕，避免读者拿到旧版继续传播时你无法证明已尽更正义务 |
| 5. 答复 | 在 issue／邮件里说明处理结果，**不争论对方动机** | "收到 → 核实 → 结论"三段即可，不写"你是恶意投诉" |

- **"通知—删除"的制度位置**：《民法典》第一千一百九十五条、第一千一百九十七条规定了网络用户／网络服务提供者的侵权通知与"知道或应当知道"责任（条号来源见第十节，属名誉权纠纷诉讼要点整理，正式引用前建议再核一次现行文本）。姿态：接到有效通知即及时采取必要措施，处置过程留痕——这是减责的关键证据。
- **不要和投诉人对线**：公开对线会把焦点从"内容是否失实"转移到"双方互骂"，你会在情绪中产出新的可诉内容；对企业投诉方而言，你的每一次公开回应都在扩大损害范围，反而强化其主张。
- **README 里该有的写法**：一句"发现内容失实请开 issue，核实后 7 日内更正或下架"。本仓库 README 末尾已加该渠道（📮 行）与「〇、这个仓库的立场」一节；fork 出去或换平台时记得把这两处一并带走。
- **GitHub 侧渠道**：DMCA 下架请求、举报 Abuse；被举报后先自查内容再申诉，不要在申诉里夹带对方公司负面评价。
