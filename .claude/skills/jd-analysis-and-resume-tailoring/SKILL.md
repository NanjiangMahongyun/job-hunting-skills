# JD分析与简历定制（借鉴 GitHub 官方 technical-job-search 框架）

## 这个 skill 干什么

两个功能：
1. **JD分析**：把岗位描述拆解成结构化信息，让你知道这个岗位到底要什么、有什么坑
2. **简历定制**：根据JD调整简历，提高匹配度，不是海投同一份简历

**参考来源**：GitHub 官方 [awesome-copilot / skills/technical-job-search](https://github.com/github/awesome-copilot/blob/main/skills/technical-job-search/SKILL.md)（MIT 协议）。本 skill 的 JD 拆解结构与简历定制 5 条原则改写自该框架，并针对中国校招/社招场景做了本地化（三方协议、社保公积金、外包签约主体等该框架没有的部分为本仓库原创）。

**参考依据**（两份知识库只作判断依据，本 skill 不复制其内容）：

- JD 考点映射到面试准备 → `knowledge-base/面试高频问题与作答框架.md`：第一部分拆出的必备条件与红旗信号，直接映射成报告"六、面试准备建议"——技能点走 2.1 项目深挖四问法，"可以反问"那几条从 3.7 反问环节的高质量清单里挑，别临场编。
- 该不该现在投 → `knowledge-base/校招与社招时间线全景.md`：判断这个 JD 现在投是否赶得上（校园线实习/秋招/春招窗口与三方时效、社招线金三银四/金九银十与 30 天交接期），据此决定投递优先级而不是先投了再说。
- 怎么用 AI 跑这一步 → `knowledge-base/AI辅助求职实操教程.md`：本 skill 输出的改写建议要落成可执行动作时按该教程的分工——AI 负责 JD 考点归纳、简历措辞与 STAR 改写，人负责核实事实与最终取舍；涉及数据（薪资、公司口碑）必须走真实检索而不是让 AI 编。

### 第0步（前置）：确认求职身份（大学生 / 社会人员）

**🎓 大学生 / 应届生**：简历重学历/实习/竞赛/课程项目；职级信号词用 built/implemented/learned；规避"主导架构"式虚高表述。

**💼 社会人员 / 在职跳槽**
- 简历**重经验成果与业绩量化**（项目规模、ROI、降本增效、团队管理）
- 必须处理：**空窗期**（如实或弱化）、**频繁跳槽**（合并/合理化）、**跳槽理由**（职业规划/成长，不贬低上家）
- 职级信号词用 led/designed/optimized 甚至 drove/architected（按实际职级）；按目标职级定简历措辞
- 注意：社招简历通常 2 页封顶，经验优先于学历

**判定规则**：优先问用户；按身份选简历模板（应届模板 vs 社招模板）、量化口径、职级信号词。

## 第一部分：JD分析

### 执行流程

拿到JD后，提取并结构化以下4个维度：

#### 1. 必备条件（Must-haves）
- 明确要求或多次重复的技能、经验年限、特定领域知识
- 这些是硬门槛，不满足大概率被筛掉

#### 2. 加分项（Nice-to-haves）
- 提到一次、写着"优先""加分""有XX经验者优先"的
- **候选人常常因为加分项自我淘汰，但这些其实是可选的**——满足必备条件就可以投

#### 3. 这个岗位实际解决什么问题
- 用2-3句话总结：公司招这个人是来解决什么业务问题的
- 从JD的业务描述、团队介绍、项目背景中推断
- 这决定了你面试时该强调什么

#### 4. 红旗信号（Red flags）
| 信号 | 风险 |
|------|------|
| "能者多劳""承担多种角色"但职责范围不清 | 职责边界模糊，什么都干 |
| 一个岗位要求10+种必备技术 | 不现实的门槛，或团队规划混乱 |
| 完全不提团队规模、技术栈、做什么产品 | 可能组织混乱 |
| "抗压能力强""能接受高强度工作" | 加班信号 |
| 薪资区间异常宽泛（如5K-20K） | 实际按最低给，或只是KPI面 |
| "接受出差/驻场"但没说补贴和周期 | 外派风险 |

### 输出格式

```markdown
# JD分析报告：[公司名] [岗位名]

## 一、必备条件（Must-haves）
- [技能1]
- [技能2]
- [经验要求]

## 二、加分项（Nice-to-haves，可选）
- [加分1]
- [加分2]
> 注意：满足必备条件即可投递，加分项不是硬门槛

## 三、这个岗位实际解决什么问题
[2-3句话总结]

## 四、红旗信号
- [信号1] → [风险说明]
- [信号2] → [风险说明]

## 五、你的匹配度
| 维度 | 你的情况 | 匹配度 |
|------|---------|--------|
| 必备条件1 | [你有/没有/部分] | 高/中/低 |
| 必备条件2 | | |

## 六、面试准备建议
- 重点准备：[基于必备条件]
- 可以反问：[基于红旗信号，如"团队目前多少人？""]
- 简历应突出：[基于岗位解决的问题]
```

## 第二部分：简历定制（针对具体JD）

### 社招简历专项（社会人员必看）

#### 处理空窗期
- 如实但不放大：可用"备考/进修/自由职业/家庭事务"合理说明，简历上不必单独列
- 面试被问："这段时间做了 X（学习/项目/提升）"，正面化，不回避

#### 处理频繁跳槽
- 短经历（<6 个月）可合并或弱化，突出稳定期经历
- 跳槽理由统一成"职业成长/方向升级"，不贬低上家
- 避免简历上出现"每家公司都只待几个月"的观感

#### 跳槽理由（简历 + 面试口径一致）
- 正面理由：职业发展/技术方向升级/平台成长/职级晋升
- 负面理由避免：钱少事多、领导差、裁员被辞（除非被问，策略性正面化）
- 简历上不需要写离职原因，但面试必答，需提前准备统一口径

#### 职级与年限匹配
- 按实际工作年限定职级信号词（见下方 5 条原则的职级表）
- 经验优先于学历：学历放靠后，项目成果/业绩放前面
- 社招简历通常 2 页封顶，删减与目标岗位无关的早期经历

### 5条核心原则（对应 [awesome-copilot / technical-job-search](https://github.com/github/awesome-copilot/blob/main/skills/technical-job-search/SKILL.md) 的 CV tailoring 五条：Match language exactly / Lead with impact / Quantify everything / Cut what does not match / Mirror seniority signals）

#### 1. 精确匹配用词
- JD写"分布式系统"，简历就写"分布式系统"，不要写同义词"大规模系统"
- ATS（简历筛选系统）和面试官都在找关键词匹配
- 但不要堆砌关键词，要自然融入

#### 2. 以影响开头
- 每条经历都要有结果："将P99延迟降低40%"，不是"参与了性能优化"
- 公式：**动作 + 具体做法 + 量化结果**
- 例：❌ "负责后端开发" → ✅ "设计并实现订单服务，支撑日均10万单，响应时间<200ms"

#### 3. 尽量量化一切
- 用户量、QPS、团队规模、节省的成本、带来的收入
- 没有精确数字时用估算："服务约X用户""提升约X%"
- 应届生可以量化：课程项目规模、竞赛排名、实习期间的产出

#### 4. 删减不匹配的内容
- 针对这个岗位定制的2页简历 > 海投的4页通用简历
- 和岗位无关的经历（如不相关的兼职、社团）可以删掉或压缩
- 技术栈按JD要求排序，最相关的放前面

#### 5. 匹配职级信号词
| 职级 | 信号词 |
|------|--------|
| 应届生/初级 | built（构建）、implemented（实现）、learned（学习） |
| 中级 | designed（设计）、optimized（优化）、led（主导） |
| 高级/专家 | drove（推动）、defined（定义）、architected（架构） |

> 应届生不要用"主导架构"这种词，用"实现了""参与了""优化了"更真实。

### 执行步骤

1. 先跑第一部分JD分析，拿到必备条件和岗位解决的问题
2. 把用户简历中的每条经历按5条原则重写
3. 调整顺序：最匹配JD的经历放最前面
4. 删减不相关内容
5. 输出定制后的简历

### 输出格式

```markdown
# 定制简历：针对[公司名][岗位名]

## 修改说明
- 原简历：[X]字/[X]页
- 定制后：[X]字/[X]页
- 主要改动：[列出3-5条关键修改]

## 定制后的简历内容
[完整简历，按JD优化]

## 为什么这么改
| 原表述 | 改为 | 原因 |
|--------|------|------|
| [原文] | [新文] | [匹配JD关键词/量化结果/删减无关] |
```

## 禁止行为

1. ❌ 禁止编造经历、技能、数字
2. ❌ 禁止关键词堆砌（为了过ATS而塞不相关的词）
3. ❌ 禁止把加分项说成必备条件吓唬用户
4. ❌ 禁止把应届生经历包装成高级别（用"主导架构"这种词）
5. ❌ 禁止删除用户真实的重要经历来"优化"
6. ❌ 禁止把含他人个人信息或公司未公开资料的原始文件（同事/推荐人姓名、客户名单、内部文档、代码、合同原件）交给第三方 AI 处理——先按《AI辅助求职实操教程》"用 AI 之前"一节去标识，只给必要文本
