# Company Due Diligence (求职向公司尽调)

## 适用场景
- 用户拿到多个offer，需要横向对比公司
- 用户准备入职某家公司，想了解风险
- 用户提到"这家公司靠谱吗"、"对比一下这几家"、"有没有坑"
- 用户提供公司名称，要求评估经营稳定性/风险/口碑
- 用户从岗位池里挑了几家/要求全部公司做尽调，准备按排名依次投递
- 用户要保留每家公司的尽调结果，方便下次直接引用

**参考依据**（两份知识库只作判断依据，本 skill 不复制其内容）：

- 工商/司法/口碑入口与引用资格 → `knowledge-base/求职信息渠道与数据源清单.md`：第一步 A/B/C/D 各维度开源时按它的工商司法章与员工口碑章查（含付费/免费口径），报告里哪些能写成事实、哪些只能标为"未经核实"，一律按它的 ✅ 事实级 / ⚠️ 只作线索 / ❌ 不得写入 分级判。
- 先定类型再叠加专属项 → `knowledge-base/公司类型画像与选择指南.md`：第一步先判目标公司属 11 类中的哪一类（大厂/国企央企/事业单位/人力外包/项目外包/研究院所/外企研发中心/银行金融科技…），再叠加该类专属的"尽调重点"与"红旗"，而不是所有公司套同一张核查表。

## 最高优先级铁律（绝对不能违反）
1. **禁止编造任何数据**：所有工商信息、司法案件、风险记录、口碑评价，必须来自实际搜索结果
2. **搜不到就明确说"未查到"**：绝对不能用"一般来说"、"通常"、"大概"来填充缺失数据
3. **每条关键信息必须标注来源**：搜索结果里没有的，一律不写
4. **区分"已查证"和"传闻/单方说法"**：口碑类信息要标注来源平台（脉脉/职友集/知乎）
5. **不主观臆断**：只陈述事实+基于事实的风险推演，不直接下"这家公司是骗子"这种结论

## 执行流程（必须按顺序）

### 第0步（前置）：确认求职身份（大学生 / 社会人员）

在开始任何检索前，**先向用户确认求职身份**，不同身份要查的风险项完全不同：

**🎓 大学生 / 应届生（校招、实习通道）**
- 关注点是"这家公司会不会坑学生"
- **本 skill 的身份差异（重点核查项）**：
  - 是否有校招/实习**培养体系**（带教机制、转正通道、实习留用率）
  - **签约主体是否为外包或第三方人力公司**（合同主体 ≠ 实际用工单位 → 派遣/外包红旗）
  - 是否**拖欠实习生报酬**（搜"[公司] 实习生 工资 拖欠"）
  - 有无被曝光的**校招毁约/砍offer**记录（搜"[公司] 校招 毁约"）

**💼 社会人员 / 在职跳槽（社招通道）**
- 关注点是"进去后权益能不能保住"
- **本 skill 的身份差异（重点核查项）**：
  - **背调是否第三方执行**（第三方机构 → 核授权边界、离职原因口径）
  - **社保实缴人数与基数**（参保人数 vs 宣称规模、是否按最低基数缴）
  - **竞业限制使用是否泛滥**（普通开发/测试岗也要求签竞业 = 制度性风险）
  - **劳动仲裁与欠税记录**（开庭公告案由含劳动争议、欠税公告）
  - **近一年裁员或经营异常**（裁员新闻、经营异常名录、突然大规模缩招）

**判定规则**：优先直接问用户；用户自述优先于简历/历史记录的任何推断，简历与记忆只作证据补充；无法确定时默认"🎓 大学生"分支，并在报告顶部标注「身份待确认」。确认后，后续检索关键词与风险评级权重按对应身份分支执行。

### 第0步附：确认数据获取方式（是否有付费 API，必问）

在开始任何检索前，**先向用户询问**是否有企查查/天眼查等工商、司法数据平台的付费调用能力：

1. **询问是否有 API Key / 付费账号**：例如"是否有企查查或天眼查的 API Key？"
2. **若有**：保留并使用该平台的**付费 API 调用**，直接获取更精确的结构化数据（精确参保人数、注册资本/实缴、完整司法案件清单、欠税、经营异常等），写入尽调报告。
3. **若没有 / 用户未提供**：启用默认**免费版**——用通用搜索（general_search / WebSearch 等）检索企查查/天眼查/国家企业信用信息公示系统/中国执行信息公开网/信用中国等**公开页面**，从搜索结果中提取信息。

**规则：**
- 用户明确提供 API Key 时才走付费通道；**绝不假设用户有 key**，更不凭空编造付费接口返回的数据。
- 免费版无法覆盖的字段（如精确参保人数、完整司法案件清单），如实写"未查到/公开渠道不全"，不编造。
- 无论付费还是免费，所有数据必须来自实际检索，禁止编造（沿用下方铁律）。
- 若用户既没提供 key 也没禁用付费，一律按默认免费版执行。

### 第0步附2：确认尽调范围（几家 or 全部，必问）

**先读岗位池，不要直接开查。** 默认读取 `memory/03-job-pool/[地区]-[方向].md`（用户指定其他文件则按指定文件），按公司去重后列出清单：

| 公司编号 | 公司（品牌名/全称待核） | 岗位数 | 岗位池最高排名/得分 | 招聘链接核验情况 |
|---|---|---|---|---|
| C1 | | | | |

**然后问用户，三选一：**
1. **指定几家**：回复公司编号，如 `C1,C3,C5-C8`；
2. **全部**：岗位池里去重后的所有公司（不是 30 个岗位，通常公司数少于岗位数）；
3. **仅第一梯队**：只查最高梯队公司。

**规则：**
- 同一公司多个岗位只做 **1 次公司尽调**，在报告里列出该公司全部岗位链接；不要按岗位重复尽调。
- 尽调报告按**公司**存档，跨方向共用；排名按**方向+筛选条件**单独生成。换方向时复用公司报告，但要先看有效期，不重复查、也不拿过期报告当现状。
- **但公司尽调只解决公司层风险**：公司评级回答“这家公司靠不靠谱”，岗位评级回答“这个岗位能不能投”。公司 🟢 不代表岗位无坑，外包/派遣/驻场、部门差异、异地、岗位时效都要在岗位层单独核；不要把公司评级复制成岗位评级。
- 用户说“所有三十个公司”时，先核对岗位池计数口径：若池里是 30 个岗位、去重后只有 W 家公司，要明确告诉用户“全部 = W 家”，不要擅自把岗位数当公司数；若用户坚持要 30 家而池里不足，先回 `job-recommender` 按公司口径补搜，不要用岗位数凑公司数。
- 公司名先核全称：品牌名（如“XX科技”）不等于工商全称；搜“[品牌名] 公司全称/企查查”确认签约主体。品牌与签约主体不一致（外包/派遣）时，两个主体都要标出来。
- 范围一经确认，写入本批尽调报告的“尽调批次”与“本批范围”字段；中途不要偷偷扩大或缩小。
- 用户选“全部”且公司数 >10 时，按每批 5-10 家推进，每批结束汇报进度，**默认继续跑完**（用户叫停才停）；**全部完成前不得输出“总排名”**，只能输出“阶段性进度表”。
- 用户中断/叫停：记录已完成、未完成清单，明确告知“本轮未完成，暂无总排名”，下次可接着跑。

### 第一步：收集基础信息
对每家目标公司，必须搜索以下维度（使用联网搜索工具，如 general_search / WebSearch；具体工具名随运行环境变化）：

**A. 工商基础信息（必查）**
- 搜索关键词："[公司全称] 企查查"、"[公司全称] 天眼查"
- 需要提取：
  - 成立时间、注册资本、实缴资本
  - 法定代表人、股东结构
  - 参保人数（判断真实规模）
  - 经营状态（存续/注销/吊销）
  - 注册地址

**B. 经营与司法风险（必查）**
- 搜索关键词："[公司全称] 被执行人"、"[公司全称] 失信"、"[公司全称] 欠税"、"[公司全称] 开庭公告"、"[公司全称] 行政处罚"
- 需要提取：
  - 是否被列入失信被执行人/限制高消费
  - 欠税记录（金额、所属期）
  - 司法案件数量、案由（劳动纠纷？合同纠纷？）
  - 行政处罚记录

**C. 业务模式与客户（必查）**
- 搜索关键词："[公司全称] 主营业务"、"[公司全称] 中标"、"[公司全称] 客户"
- 需要提取：
  - 是自研产品还是外包/项目制
  - 主要客户群体（政企/互联网/海外）
  - 是否高度依赖单一客户
  - 最近中标项目（判断业务活跃度）

**D. 员工口碑与职场评价（选查但尽量查）**
- 搜索关键词："[公司全称] 怎么样 加班"、"[公司全称] 脉脉"、"[公司全称] 职友集"、"[公司全称] 面试经验"
- 需要提取：
  - 加班情况（大小周？996？）
  - 薪资发放是否及时
  - 人员流动率（从招聘信息频繁度判断）
  - 负面评价集中点（社保？绩效？管理层？）

**E. 招聘岗位与链接复核（本批范围内必查）**
- 从岗位池读取该公司**全部岗位**（不只最高分那一个），逐条打开招聘链接：
  - 页面公司/岗位/地点是否与岗位池一致
  - 是否仍在招（在招/已关闭/状态不明）
  - 是否需要登录/跳 APP
  - 记录核验时间与投递方式
- 失效/已关闭岗位：从最终投递清单剔除，并在报告中保留“原链接 + 核验时间 + 失效原因”；能补搜到替代岗就补，补不到不要硬凑。
- 状态不明/需登录且无法核对：在报告链接表逐条标注，不放进“可直接投递”清单，投递前再核。
- 报告里的招聘链接必须带核验日期；超过 7 天未复核的，投递前重新打开确认。
- **“能打开”不等于“不用登录”：** BOSS/猎聘/智联等平台投递通常要登录账号、上传简历；报告写清投递方式，不承诺“点开即投”。

**数据真实与时效（强制）：**
- 每条关键事实写来源 URL + 访问日期；搜索摘要只能当线索，尽量打开原页。
- 工商/司法基础数据有效期 90 天；在招状态/员工口碑有效期 30 天；超过有效期引用先复核，不得把旧数据写成现状。
- 无联网能力时停止尽调，告知用户无法核验；不得凭记忆写工商、司法、口碑或链接。

### 第二步：风险评级
对每家公司，基于查到的事实给出风险等级：

| 风险等级 | 判定标准（满足任一） |
|---------|-------------------|
| 🔴 高风险 | 失信被执行人/欠税大额/经营异常/参保人数<10且成立超3年/大量劳动纠纷 |
| 🟡 中风险 | 有司法案件但已结案/历史欠税已结清/规模小但业务稳定/口碑两极分化 |
| 🟢 低风险 | 成立5年以上/参保人数稳定/无重大风险记录/口碑整体正面 |

**注意**：评级必须基于查到的事实，不能因为"看起来像"就给评级。查不到足够信息时，标注"数据不足，暂无法评级"。

**评级有效期：** 报告顶部写查询日期；30 天内可直接用于投递决策，30-90 天引用前复核在招/口碑，超过 90 天工商/司法关键项也要重查。历史报告不删除，但不得把旧评级直接当现状。

### 第三步：完成度闸门（未全部完成不得出总排名）

生成横向对比和总排名前，先逐家核对：
- 本批范围 N 家，是否已有 N 份独立尽调报告？缺哪家？
- 每家报告是否包含：查询日期、数据来源、公司风险评级、该公司全部岗位链接与核验日期、每个岗位的用工性质/岗位级风险？
- 用户中途取消/无法查到的公司，是否在“未纳入/数据不足”清单里写明原因？

**闸门规则：**
- N 家全部完成（或每家都有明确的“已排除/数据不足/用户取消”结论）→ 才能进入第四步，输出“横向对比与尽调后总排名”。
- 有缺失 → 只输出“阶段性进度表”，标题不得写“总排名”，并列出还差哪几家。
- 用户只选了其中几家 → “全部完成”指**选中的这几家**全部完成，不是要求把岗位池所有公司都查完；未选中的公司在报告中单列“未纳入本轮”。

### 第四步：横向对比 + 尽调后总排名

**4.1 横向对比（公司级）**：按下方模板输出核心指标对比表。公司数 ≤8 用横向宽表；>8 家（尤其“全部30家”）必须改成“每行一家公司”的长表，否则 30 列宽表无法阅读；总排名仍按岗位逐行输出。

**4.2 重新排名（岗位级）**：完成本批所有公司尽调后，**必须基于尽调事实对原岗位池排名进行修正**，产出尽调后总排名。

**重新排名规则：**
- 原岗位池得分（job-recommender 第五步的加权总分）作为"岗位匹配基准分"
- **公司风险等级**作为重大调整因子（同一公司所有岗位共用）：
  - 🟢 低风险：不做负向调整
  - 🟡 中风险：在原得分基础上 **-1 分**
  - 🔴 高风险：**直接移出推荐序列**，不参与排名，仅在"已排除"段列出并说明原因
- **岗位级风险单独判断，不能用公司评级代替**：
  - 每个岗位必查：用工性质（正编/外包/派遣/驻场）、所属部门/项目、工作地点、在招时效与链接、薪资结构（底薪/绩效/加班费）、用户硬条件（双休/加班工资）是否在 JD 层面核实。
  - 岗位级硬伤（与用户硬条件冲突的外包/派遣/驻场、异地、已失效、薪资结构不符）→ **直接移出排名**，列入"已排除岗位"，不靠降分保留。
  - 岗位级减分项（项目末期、部门口碑差、通勤过远、职责与 JD 不符）→ **-0.5 至 -1 分**，在"岗位风险"列写明依据。
  - 岗位信息无法核实 → 标"岗位风险待核"，不得默认低风险。
- 尽调关注点（口碑负面/劳动纠纷/社保问题等）作为微调因子：视严重程度 **-0.3 至 -0.8 分**
- **调整后总分 = 岗位匹配基准分 + 公司风险调整 + 岗位级调整 + 关注点微调**
- 公司级调整与岗位级调整必须**分列展示**，不合并成一个笼统的“风险”列；同一公司多个岗位共用公司风险调整，岗位级调整各自计算，原得分不重复加总。
- 备选池岗位：默认不参与总排名，单列“备选投递清单”；用户明确要求“全部岗位都排”时，单独出“含备选排名”，不与达标排名混排。
- 数据不足的公司：不强行给分，列“待补查”，不进入总排名。
- 公司所有岗位都失效：保留公司尽调报告备查，但不进入总排名；在“未纳入/失效”清单写明原因。
- 跨批次累计：用户要求累计时，按 `memory/04-due-diligence/companies/尽调索引.md` 读取所有已完成报告，另存新的累计排名文件，不覆盖旧排名。

**输出要求：**
1. 为每个尽调公司生成独立的尽调报告文件（一家一份，留存可引用；哪怕结论是“数据不足/已排除”，也要有文件）
2. 本批全部完成后，生成横向对比 + 尽调后总排名 + 投递作战清单
3. 更新尽调索引（公司层）与排名索引（排名层），记录最新报告路径、评级与对应岗位池版本
4. 所有文件均须落盘保存，并在报告里用相对路径互链

## 输出格式

### 单家公司尽调报告格式
```markdown
# [公司全称] 求职尽调报告
**查询时间：** YYYY-MM-DD HH:mm
```

## 常见场景处理

### 场景1：小微企业（参保人数<30）
- 重点关注：薪资发放稳定性、社保是否按实际基数缴纳、项目回款风险
- 搜索："[公司名] 拖欠工资"、"[公司名] 劳动仲裁"
- 提示：小微企业抗风险能力弱，项目制公司尤其要注意回款节奏

### 场景2：政企/国企外包类公司
- 重点关注：是否是正式员工还是外包驻场、社保公积金缴纳标准、项目周期稳定性
- 搜索："[公司名] 中标"、"[公司名] 国家电网"（或对应行业关键词）
- 提示：高度依赖单一央企客户的公司，客户预算收缩时风险大

### 场景3：成立1-2年的新公司
- 重点关注：股东背景、融资情况、团队来源
- 搜索："[公司名] 融资"、"[创始人名] 背景"
- 提示：新公司数据少，风险不确定性高，建议把薪资/试用期条款谈清楚

### 场景4：搜到大量负面信息
- 不要直接说"这家公司是坑"
- 客观陈述："根据XX平台X条评价，集中反馈的问题是XXX"
- 标注评价的时间分布（是最近的还是几年前的老黄历）

### 场景5：用户只选几家 / 要求全部

- **只选几家**：只对选中公司出总排名；其余在“未纳入本轮”列明，不冒充已尽调。
- **全部**：按公司去重后逐家查；超过 10 家分批，全部完成前只出进度表；不要用岗位数冒充公司数。
- **中途叫停**：出“阶段性进度表”，标未完成，不下总排名结论。

### 场景6：岗位链接打不开 / 已关闭

- 区分登录墙、APP 跳转、真失效：登录墙标“需登录”，真失效标“已关闭/失效”。
- 失效岗位从投递清单移除，保留原链接与核验时间；能补搜替代岗就补，补不到如实减少，不硬凑。
- 报告里的链接必须带核验日期；超过 7 天投递前重新打开确认。

### 场景7：公司评级 🟢，但岗位是外包/驻场

- 公司层尽调没问题，不代表这个岗位是正编；先看签约主体、工牌/工位/管理关系、社保由谁缴。
- 招聘写着“XX大厂项目”“驻场XX银行”的，按外包岗处理，在岗位风险列写明；用户要求正编时直接排除，不靠公司评级放行。
- 同一公司的总部正编、外包项目组、异地分部不能共用一个“🟢”，按岗位分别标注。

## 禁止行为清单
1. ❌ 禁止编造参保人数、注册资本、案件数量等任何数字
2. ❌ 禁止用"据了解"、"一般来说"这种没有来源的表述
3. ❌ 禁止把"未查到"等同于"没有"
4. ❌ 禁止直接下"这家公司不靠谱"的结论，要给出事实+推演
5. ❌ 禁止预测公司未来会不会倒闭，只说"基于当前数据，存在XX风险"
6. ❌ 禁止未完成本批范围内全部公司就输出“总排名”；只能出“阶段性进度表”
7. ❌ 禁止一家公司多个岗位只列一个链接；必须列出岗位池中该公司的全部岗位链接
8. ❌ 禁止把已关闭/失效链接留在投递清单里不标注；禁止把登录墙当成“已核验可投”
9. ❌ 禁止把“30个岗位”当成“30家公司”做尽调而不说明口径
10. ❌ 禁止引用过期尽调报告不重新核验；旧报告是历史，不是现状
11. ❌ 禁止编造招聘链接、在招状态或核验时间
12. ❌ 禁止用公司风险等级代替岗位风险；公司 🟢 不能直接写成岗位 🟢，外包/驻场/异地/失效必须在岗位层单独标注

## 数据源优先级
1. 企查查/天眼查/国家企业信用信息公示系统（最权威）
2. 中国执行信息公开网、裁判文书网（司法数据权威）
3. 信用中国（行政处罚、欠税）
4. 公司官网、官方公众号（业务模式）
5. 脉脉、职友集、知乎、小红书（员工口碑，注意区分真假）
6. 招投标网站（项目活跃度）
