# 入职后在岗管理（入职后 → 评估该不该走）

## 这个 skill 干什么

针对你入职的这家具体公司 + 你，管理**入职后在岗**这段：

1. **在岗策略**：怎么过试用期、怎么融入、怎么留痕、怎么在绩效博弈里不吃亏
2. **风险监测**：这家公司/岗位有没有恶化信号（经营/裁员/被边缘化），提前预警

**和现有 skill 的边界（引用但不重复写）：**
- 通用软技巧（visibility/沟通/拒绝/留痕/同事关系）→ `knowledge-base/职场小技巧与人情世故.md`
- 离职交接/竞业/社保/背调细节 → `knowledge-base/离职与背调合规手册.md`
- 在职期间核对五险一金缴纳记录 → `knowledge-base/五险一金与个税实操手册.md`：第二步风险监测出现"工资/社保拖延"怀疑时用它——按其 2.2 查实际缴费基数与缴存明细（去哪查见第五章），把怀疑变成留痕证据，顺带对照其红旗清单识别"按最低基数缴""自愿放弃社保"。
- 想走/跳槽的时机与步骤 → `.claude/skills/job-switch-decision/SKILL.md`

**同类现状（已调研，2026-10）**：github 上成熟求职 skill 集中在"求职动作"段（JD 分析/简历/面试/offer 评估），不覆盖在职管理；"入职后在岗管理 + 风险监测"无现成独立成熟 skill（claude-office-skills 的 onboarding 是 HR 视角流程自动化，非求职者个人在岗策略）——本 skill 为差异化补位，内容为自建方法论，不复制任何第三方。

## 执行流程（必须按顺序）

### 第0步（前置）：确认求职身份（大学生 / 社会人员）

在确认处境前，**先向用户确认求职身份**，在岗管理的重点完全不同：

**🎓 大学生 / 应届生（实习、应届试用期通道）**
- **本 skill 的身份差异（在岗重点）**：
  - **实习转正条件是否书面化**：转正标准、留用名额、评估人必须落到书面/邮件；只有口头承诺 = 高毁约风险
  - **试用期考核标准与解除风险**：录用条件是否客观可量化（"主观评价不合格"= 高危）、试用期时长与工资下限、实习协议 vs 劳动合同的差异（在校生不建立劳动关系、无强制社保）

**💼 社会人员 / 在职跳槽（社招通道）**
- **本 skill 的身份差异（在岗重点）**：
  - **绩效与晋升周期**：考核节点、评级分布、晋升窗口在哪个季度（决定何时谈涨薪、何时更新简历）
  - **在职更新简历与留痕**：保密求职（不在公司设备/内网投递）、成果留痕归档到个人（离职举证 + 下份简历素材）
  - **竞业与保密在职风险**：在职期间接触的核心资料不外传、确认是否签过竞业协议与触发条件，避免离职即被追责

**判定规则**：优先直接问用户；用户自述优先于简历/记忆的任何推断，简历与归档只作证据；无法确定时默认"🎓 大学生"分支，并在报告顶部标注「身份待确认」。确认后，在岗策略与风险监测清单按对应身份分支输出。

---

### 第0步附：确认当前处境（先问，不靠猜）

必须向用户确认：
- 身份：🎓 大学生/应届生 还是 💼 社会人员（第0步（前置）已确认，决定走哪条分支）
- 公司：名称 / 行业 / 规模 / 大致经营状况 / 岗位 / 直属上级风格
- 自己：入职时间 / 是否在试用期 / 角色职级 / 核心诉求
- 用户对现状的一句话自述（有没有不对劲的信号）

> 规则：先问用户处境，用户自述优先，不凭简历或猜测推断。

---

### 第一步：在岗策略（针对这家公司 + 你）

#### A. 试用期目标（前 30/60/90 天）
| 阶段 | 目标 | 关键动作 |
|------|------|---------|
| 前30天 | 摸清业务与团队 | 了解业务链路、对齐直属上级的考核预期、找到"谁说了算" |
| 前60天 | 出第一个可见成果 | 接一个能落地、能展示的活，留下产出记录 |
| 前90天 | 建立信任与定位 | 让上级认可"这个人能独立产出"，明确转正标准 |

#### B. 融入与 visibility（引用职场小技巧，重点提取）
- **对齐预期**：入职第一周就跟直属上级确认"我这个岗位这季度最重要的 1-3 件事是什么"，避免方向跑偏
- **留痕防甩锅**：重要沟通邮件/群聊留底，成果主动同步给相关方（详见职场小技巧"工作留痕"）
- **找到关键人**：谁是决定你转正/绩效/资源的裁判，优先对齐 TA
- **主动暴露风险**：进度有风险提前说，别到截止日爆雷——主动说=负责，被动爆=能力问题

#### C. 绩效博弈（试用期/季度考核前）
- 提前问清考核指标怎么算，把"做了什么"翻译成"带来了什么结果"
- 保留产出证据（文档/数据/上线记录），考核时能拿出来
- 指标不合理 → 用事实协商（"这项依赖他人，需协调X资源"），不硬扛

---

### 第二步：风险监测（这家公司 + 岗位）

#### A. 公司层面恶化信号（预警清单）
| 信号 | 含义 | 应对 |
|------|------|------|
| 工资/社保拖延发放 | 资金链紧张 | 开始留意，留存考勤/合同证据 |
| 裁员/业务收缩/砍项目 | 经营恶化 | 关注是否波及自己部门 |
| 老板/高管频繁失联或换血 | 管理混乱 | 降低预期投入 |
| 承诺的绩效/年终/期权不兑现 | 画饼 | 及时止损考虑 |
| 办公场地异常（退租/搬迁） | 收缩信号 | 观察 |

#### B. 岗位层面信号（被边缘化）
- 职责被逐渐架空、重要会议不带我
- 承诺的晋升/方向被无限拖延
- 长期只做杂活、无成长
- 绩效被打低分且不给明确改进路径

**规则**：监测到 2 个以上预警信号 → 联动 `.claude/skills/job-switch-decision/SKILL.md` 进入"是否该走"评估，别等到被动。

## 禁止行为

1. ❌ 不编造公司经营/风险事实——只基于用户提供的信号和可查信息分析
2. ❌ 不重复写 职场小技巧/离职手册 已覆盖的内容——本 skill 只做"在岗策略 + 风险监测"的整合
3. ❌ 不制造焦虑——只在出现真实预警信号时才提示跳槽评估
4. ❌ 不教用户消极怠工或恶意隐瞒——留痕是为了自证，不是甩锅
