# 求职谈判综合分析（简历 + 公司尽调 → 谈判筹码）

## 这个 skill 干什么

用户拿到 offer 准备谈薪时，把**用户简历**和**目标公司尽调结果**放在一起分析：
- 从简历里挖出用户自己可能没意识到的优势
- 从公司尽调里找出公司的软肋和压力点
- 把"我的优势"和"公司的痛"匹配起来，变成实实在在的谈判筹码
- 生成针对这家公司的定制化话术和策略

**核心逻辑**：谈判不是乞讨，是交易。你给公司解决问题，公司给你对应报酬。你的优势越能命中公司的痛点，议价权越大。

**参考依据**：通用的优势类型和公司劣势类型见 `knowledge-base/自身优势与公司劣势通用框架.md`。本 skill 在通用框架基础上，根据用户的具体简历和目标公司做定制化匹配。

- 定价折算 → `knowledge-base/五险一金与个税实操手册.md`：第六步匹配出筹码、"四、谈判策略"报目标薪资时，用它把 offer 月薪折成总包与到手，把"社保按最低基数缴""公积金 5%"这类劣势量化成要求底薪补偿的数额，而不是只当口号。
- 劣势识别与筹码对照 → `knowledge-base/公司类型画像与选择指南.md`：第五步提取劣势前，先按 11 类公司给目标公司定性，再对照该类的薪资结构骨架与"尽调重点/红旗"，判断哪些算制度性劣势、哪类补偿筹码才成立（外包类的签约主体问题、国企央企的编制差异、初创的期权兑现各有各的打法）。
- 💼 社招分支的定价与退路 → `knowledge-base/社招跳槽谈判指南.md`：第0步（前置）判定为 💼 时，用它替代校招生"按岗位定薪"的思路——第九节把当前总包算全（定价的事实基础）、第十节判断涨幅只看能核实的因素、第十一节多 offer 比较与"用 A 谈 B"的话术边界、第十二节在职/离职的议价力差异与口径一致、第十四节谈崩信号与何时放手。⚠️ 该指南只处理**真实存在**的薪资与 offer，虚报当前薪资、伪造对手 offer 一律不用。

## 执行流程（必须按顺序）

> 使用前的知识库导览（14 份资料，标了哪些可独立通读、哪些用到再查）见 `README-使用索引.md` 的「使用前建议：知识库怎么读」章节，不属于本 skill 执行流程。

### 第0步（前置）：确认求职身份（大学生 / 社会人员）

开始前先确认用户求职身份，不同身份走不同谈判逻辑：

**🎓 大学生 / 应届生（校招、实习通道）**
- 卖点 = 学历/潜力/实习/竞赛/项目；薪资按校招定薪，谈判空间小
- 谈判侧重：校招薪资三档、政府补贴筹码、可塑性筹码、offer横向比较
- 筹码库见下文「应届生专属筹码库」

**💼 社会人员 / 在职跳槽（社招通道）**
- 卖点 = 经验深度/项目成果/业绩量化/晋升线；**跳槽加薪逻辑（期望涨幅15-30%）**
- 谈判侧重：**跳槽涨幅定价（基于薪资流水/offer）、在职 vs 离职状态、竞业限制、社保公积金连续性、背调、离职交接**
- 警惕：公司用"应届生标准"压价、以"可塑性"压经验价值；跳槽务必拿到"涨薪+职级"而非平薪

**判定规则**：优先问用户，用户自述优先；无法确定时默认"大学生"分支并标注待确认。谈判目标薪资、筹码库、话术按身份走对应分支。

### 第0步：加载通用框架
先读取 `knowledge-base/自身优势与公司劣势通用框架.md`，了解：
- 求职者常见的4大类优势（身份/技能/经验/性格）
- 公司常见的4大类劣势（经营压力/人才吸引力/制度性/岗位特定）
- 通用匹配速查表

然后在下面的步骤中，从通用框架里筛选出**符合用户具体情况**的条目，做定制化分析。

### 第一步：确认用户求职方向与自我定位（必须先问，优先级最高）

**在开始任何分析之前，必须向用户确认以下信息，不得只从简历推断：**

1. **求职方向**：目标岗位/方向（如"AI Agent 应用研发"、"RAG/大模型应用"、"Java 后端"、"测试"等）；用户说"不设限"时，也要确认大致属于哪种技术类型。
2. **自我定位/自述**：用户自己如何描述自己的优势与定位（如"主力是 AI Agent，Java 只是熟悉不是优势"、"有 Agent 后重要的是决策"等）。
3. **目标地区**：求职城市/区域（如"南京"、"长三角"）。
4. **其他关键自述**：用户主动补充的、简历上看不到的判断（行业看法、职业理念、转型意图等）。

**为什么必须有这一步**：简历记录的是"过去做了什么"，可能滞后于用户当下的求职方向和自我认知。只从简历推断，容易把用户不主打的技能当作优势（典型教训：简历以 Java 后端为主，但用户真实主力是 AI Agent——按简历推断就会判断错方向）。**用户的自述优先级高于简历推断**，简历只作为证据补充。

**规则**：
- 用户明确提供的求职方向与自述 = 最高优先级输入，覆盖简历推断结果。
- 用户未明确时，才结合简历推断，但必须标注"基于简历推断，建议用户确认"。
- 后续"优势提取"和"行业背景分析"的方向，一律以本步确认的结果为准。

### 第二步：提取用户简历中的核心优势

让用户提供简历（粘贴文本或上传文件），从中提取以下维度。**提取时围绕第一步确认的求职方向，优先提取与该方向匹配的优势**（如方向是 AI Agent/RAG，则 RAG 实战、Agent 驱动开发等优先；不主打的技能只作"工具"列出，不当作核心优势）：

**A. 硬技能优势**
- 编程语言/框架/工具的熟练度和深度
- 有没有稀缺技能（如特定中间件、云原生、AI 相关）
- 证书、竞赛获奖、专利、论文

**B. 项目经验优势**
- 项目规模（用户量、数据量、并发量）
- 个人角色和具体贡献（不是"参与了"，而是"我做了X，带来了Y结果"）
- 有没有从 0 到 1 的经验
- 有没有性能优化、降本增效的量化成果

**C. 实习/工作经历优势**
- 大厂/知名公司背书
- 对口行业经验（比如面金融公司，有金融项目经验就是大优势）
- 转正经历、优秀实习生评价

**D. 软实力优势**
- 带团队/带新人经验
- 跨部门协作经验
- 紧急问题处理经验

**E. 身份优势**
- 应届生身份（企业可领补贴，见下方筹码库）
- 学历/学校优势
- 可立即到岗 / 可提前实习

> **提取原则**：量化优先。"提升了性能"不算优势，"将接口响应从 800ms 降到 120ms"才算。用户简历没写的，不要编造，但可以提示用户补充。

---

### 第三步：行业背景分析（基于第一步确认的求职方向）

完成求职方向确认和优势提取后，**必须自动调用 `.claude/skills/industry-background-analyzer/SKILL.md`（industry-background-analyzer）**，针对用户确认的求职方向联网搜索并生成一份行业背景报告，作为后续优势-劣势匹配和筹码定价的底座。

**为什么必须有这一步**：行业形势决定你的议价权——需求>供给时你有筹码，供给>需求时公司有筹码。没有行业背景，谈薪就是拍脑袋。

**执行要求：**
- 行业方向：**以第一步用户确认的求职方向为准（用户自述优先，禁止只从简历推断）**，如"AI Agent / RAG 大模型应用"
- 目标地区：第一步确认的目标城市（如"南京"、"长三角"）
- 必须实际联网搜索，覆盖：行业动态（近3-6个月）、发展趋势、就业市场数据（招聘量/薪资/竞争）、高校专业供给、政策影响、头部公司动态
- 所有数字标注来源；搜不到写"未查到"；禁止编造
- 输出的行业薪资水平（25/50/75 分位）直接用于输出格式"四、谈判策略"的目标薪资定价

> 关联 skill：`.claude/skills/industry-background-analyzer/SKILL.md` 是本步骤的执行工具。行业方向未确认时先回第一步询问，不要从简历猜。

---

### 第四步：确定目标公司（尽调前置，必做）

进入公司尽调前，必须先确定目标公司，**不能跳过、不能默认用户已有公司**：

1. **先询问用户是否已有想好的公司**：
   - **有** → 记录目标公司名称、所在地点 → 直接进入下一步尽调。
   - **没有 / 只想要合适公司** → 自动调用 `.claude/skills/job-recommender/SKILL.md`（job-recommender），**基于第一步确认的求职方向 + 第二步提取的核心优势 + 第三步的行业趋势，全网搜索合适的公司/岗位**：
     - **方向匹配**：优先该方向的岗位（如 AI Agent / RAG 大模型应用研发）
     - **地区匹配**：第一步确认的目标地区（如南京、长三角）
     - **趋势匹配**：结合第三步行业趋势，优先风口期/政策驱动方向的头部与成长型公司
     - **风险初筛**：结合 company-due-diligence 的免费版（无 key 时）对候选公司做基础工商/口碑筛查，避开高危（🔴）
     - **输出**：候选公司清单（公司名、岗位、方向契合度、地区、薪资参考、风险等级），供用户选定
   - 用户选定候选公司后，才进入下一步公司尽调。

**为什么必须有这一步**：尽调的前提是有明确的尽调对象。没有目标公司时直接尽调是空转；应让 AI 按用户方向+优势+行业趋势全网匹配公司，选定了再深入尽调，避免"为了尽调而尽调"。

> 关联 skill：`.claude/skills/job-recommender/SKILL.md` 是"无目标公司"时找公司的执行工具；`.claude/skills/company-due-diligence/SKILL.md` 是选定后的风险核查工具。

### 第五步：提取公司尽调中的劣势和压力点

如果用户已经跑过 `company-due-diligence`，直接引用结果。如果没有，引导用户先做尽调，或根据用户提供的公司信息做基础分析。

从尽调中提取以下维度：

**A. 经营压力（公司急着用人的信号）**
- 成立时间短、融资轮次靠后（烧钱期，急需出成果）
- 项目中标多但人手不足（业务扩张期）
- 核心人员离职后的补位期
- HC 即将到期（Q4 尤其明显）

**B. 人才吸引力劣势（公司不好招人的信号）**
- 脉脉/职友集负面评价多（加班、拖欠、管理乱）
- 地理位置偏、通勤不便
- 薪资在行业中偏低
- 公司知名度低（候选人不愿意来）
- 技术栈老旧（有经验的人不愿意来）

**C. 制度性劣势（可以转化为谈判筹码的点）**
- 社保按最低基数缴纳 → 隐性降薪，可要求更高底薪补偿
- 大小周/996 无加班费 → 时薪低，可要求签字费或更高底薪
- 试用期长/工资打折多 → 可要求缩短试用期或提高试用期工资
- 年终奖不写进 offer → 可要求提高底薪或签字费替代
- 公积金比例低（5%）→ 可要求提高比例或补贴补偿

**D. 岗位特定压力**
- 岗位挂了很久还在招（急缺人）
- JD 要求高但薪资区间低（招不到人）
- 团队规模小，一个人当两个人用

---

### 第六步：优势-劣势匹配（这是核心）

把第二步的优势和第五步的劣势做匹配，生成谈判筹码。

**匹配公式：我的优势 → 解决公司的什么问题 → 值多少钱**

| 我的优势 | 公司的痛 | 谈判筹码 |
|---------|---------|---------|
| 有同类项目经验 | 新项目急着上线，没人带 | "我可以直接上手，节省 2-3 个月培养期" → 要求更高定级/底薪 |
| 有大厂背书 | 公司知名度低，招人难 | "我的加入可以提升团队技术影响力" → 要求签字费 |
| 可立即到岗/提前实习 | HC 快到期，项目等着人 | "我可以下周就到岗" → 要求入职奖金 |
| 掌握稀缺技术 | 团队缺这块能力 | "这方面目前团队没人懂，我来了可以直接补位" → 要求技术津贴/更高职级 |
| 应届生身份 | 公司可领政府补贴 | 企业实际用人成本低 → 要求更高底薪 |
| 有性能优化量化成果 | 公司产品性能差，用户投诉 | "我之前把X从Y优化到Z" → 要求更高定级 |

---

### 第七步：生成谈判筹码清单

按优先级排序，输出：

**🔴 硬筹码（对方很难拒绝的）**
- 基于公司经营压力的筹码（急着用人、HC到期）
- 基于稀缺技能的筹码（团队没人会的技术）
- 基于可立即到岗的筹码

**🟡 软筹码（可以协商的）**
- 基于大厂背书的筹码
- 基于项目经验的筹码
- 基于学历/竞赛的筹码

**⚫ 补偿筹码（底薪谈不动时用的）**
- 签字费（最容易拿到，不进薪酬体系）
- 绩效保底（前3-6个月按全额发）
- 调薪时间点写进 offer（"入职6个月评估调薪"）
- 补贴（餐补、交通补、住房补）
- 试用期缩短
- 年假增加
- 远程/弹性工作
- 培训预算/考证报销

---

### 第八步：生成定制化话术

根据筹码清单，生成针对这家公司的具体话术。

**话术结构：表达意愿 + 展示价值 + 提出要求 + 留有余地**

示例模板：
> "我对【公司名】的【业务方向/技术栈】非常认可，也很希望能加入。面试时【X总】提到团队目前在【某个痛点】，我在【之前的项目】中正好做过【相关成果】，可以直接上手帮团队解决这个问题。基于我的经验和目前南京同岗位的市场行情，我期望薪资是【X-Y K】。如果底薪空间有限，我们也可以看看签字费、绩效保底或者调薪时间点能不能做一些调整。"

**针对公司劣势的反制话术：**

| 公司情况 | 你的话术 |
|---------|---------|
| 社保按最低基数交 | "我注意到社保缴纳基数的问题，这部分对我实际收入影响比较大，能不能在底薪上做一些补偿？" |
| 大小周无加班费 | "了解到团队节奏比较快，我可以适应。不过考虑到工作时长，希望薪资上能有所体现。" |
| 年终奖不写进offer | "年终奖这块我理解和业绩挂钩，那能不能把前6个月的绩效保底写进offer？这样双方都有预期。" |
| 试用期6个月打8折 | "我对自己的能力有信心，能不能试用期缩短到3个月？或者试用期工资按全额发？" |
| 公司知名度低 | "我选择贵公司是看好业务方向，不过也希望薪资能体现我的经验价值。" |

## 社会人员专属筹码库（社招/跳槽用）

### 1. 跳槽加薪逻辑（核心）
- 社招薪资不是"校招定薪"，按**当前薪资流水 + 期望涨幅（15-30%）**定价
- HR 问"期望涨幅"：合理报 20-30%，底线 15%；平薪跳槽要额外理由（平台/方向/职级）
- **薪资流水/个税/社保记录**是社招议价硬证据，提前整理好

### 2. offer 比较筹码
- 手上有多个 offer 是最大筹码："另一家给了 X，我更看好贵司，薪资能否对齐？"
- 但不要虚报 offer（背调会穿帮）

### 3. 在职 vs 离职状态筹码
- 在职跳槽：公司通常愿意加钱挖（"让他愿意走"），可要求更高涨幅
- 离职（裸辞）：议价偏弱，但"可立即到岗"是筹码（HC 急着要人时）

### 4. 竞业限制筹码
- 若上家有竞业协议，新公司可能需承担竞业补偿或风险——可作为谈判点（要求更高定级/补偿）
- 新公司若要你签竞业，谈判竞业补偿金、范围与期限

### 5. 社保/公积金连续性筹码
- 断缴影响买房/落户/医保——跳槽要求"入职即缴""不空窗"
- 公司若拖延缴纳，可要求衔接安排

### 6. 职级筹码
- 社招谈**定级**比加薪更重要：涨薪但职级不变，下次跳槽基数吃亏
- 要求明确职级 + 晋升通道

## 应届生专属筹码库（直接用）

这些是应届生独有的、很多人不知道的谈判筹码：

### 1. 政府补贴筹码
企业招用应届生可以领：
- 一次性扩岗补助 1000元/人
- 小微企业社保补贴（全额，最长12个月）
- 税收优惠（每人每年6000元，连续3年）

**话术**："我了解到南京对招用应届生有多项补贴，企业的实际用人成本应该比我的薪资数字低一些，这也让我更有信心为公司创造价值。"

### 2. 可塑性筹码
- 没有不良工作习惯，更容易融入团队技术栈
- 学习能力强，对新技术接受快
- 用人部门喜欢应届生（听话、能加班、成本低）

**话术**："我虽然经验不多，但学习能力强，之前在【项目】中【快速掌握了X技术】，可以很快适应团队的技术栈。"

### 3. 校招 HC 独立预算
校招和社招预算分开，HR说"没有预算"往往不准确。

### 4. 无家庭负担
客观上更能适应高强度节奏（但**不要主动承诺加班**）。

## 禁止行为

1. ❌ 禁止编造简历中没有的优势
2. ❌ 禁止编造公司尽调中没有的劣势
3. ❌ 禁止承诺"一定能谈到X K"
4. ❌ 禁止教用户撒谎（虚报薪资、伪造offer）
5. ❌ 禁止鼓励用户为了钱盲目接受高风险公司
6. ❌ 禁止把口头承诺算进确定收入

## 使用示例（**虚构示例**，仅演示输入格式，不对应任何真实公司或个人）

**用户输入**：
> 这是我的简历：[粘贴简历]
> 公司是某市一家做政企项目的小公司（示例名 XX 科技），尽调显示参保人数十几人、有若干条劳动仲裁记录，员工社区里反馈大小周。offer 给的是月薪 8K，试用期 6 个月打 8 折，社保按最低基数交。我该怎么谈？

**输出**：按上述格式生成完整分析报告，重点突出：
- 简历中的项目经验如何匹配政企项目需求
- 公司规模小+劳动仲裁+大小周+社保最低基数 = 多个谈判筹码
- 建议目标薪资 9-10K，底线 8.5K（示例数字；实际目标价按第一步确认的方向与行业薪资行情定）
- 底薪谈不动就争取签字费、绩效保底、缩短试用期
