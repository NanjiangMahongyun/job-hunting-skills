当前技能流程总览 v1.0 · 2026-10-22

主链路：从「发送简历」到「谈判分析报告 + 记忆归档」，以 job-negotiation-strategist 为主线，联动 job-recommender 岗位/公司推荐（目标30个）、company-due-diligence 公司尽调、industry-background-analyzer 行业背景分析、memory-manager 记忆库管理 · 第0步先确认 🎓 大学生 / 💼 社会人员，12 个 skill 全覆盖 · 面试准备靠知识库《面试高频问题与作答框架》《校招与社招时间线全景》《公司类型画像与选择指南》供判断依据 · 入职后闭环：onjob-management 在岗管理 → job-switch-decision 跳槽决策 → severance-calculator 补偿维权 · 元维护：skill-upgrade-maintainer
📄 用户发送简历 入口
提供简历文件 / 粘贴文本 + 目标公司信息
① 确认求职身份 全部 12 个 skill 的第0步 必问 · 先于一切分析
判定：大学生（校招/实习） or 社会人员（社招/跳槽）。规则：优先问用户，用户自述优先于简历/记忆推断；无法确定默认大学生并在报告顶部标注「身份待确认」。该前置已写进每个 SKILL.md
🎓 大学生 / 应届生
校招+实习通道；卖点=学历/潜力/实习/竞赛/项目；硬条件含实习日薪、校招薪资；走应届筹码库
💼 社会人员 / 跳槽
社招+猎头/内推通道；卖点=经验/业绩/职级；硬条件含工作年限、在职离职、期望涨幅15-30%、背调、社保；走社招筹码库/维权/简历专项
② 读取简历 job-negotiation-strategist
解析简历内容：技能、项目、经历、证书（仅作证据补充，不作方向判断依据）
③ 确认求职方向与自我定位 job-negotiation-strategist 第一步 必问
询问：求职方向 / 自我定位自述 / 目标地区。规则：用户自述优先于简历推断（避免按简历猜错方向）
④ 提取简历核心优势 job-negotiation-strategist 第二步
围绕已确认方向提取（如 AI Agent/RAG → RAG 实战、Agent 驱动开发优先）；量化优先。社招重经验/业绩量化
⑤ 行业背景分析 industry-background-analyzer
基于③确认方向联网搜索：行业动态 / 发展趋势 / 就业薪资 / 高校供给 / 政策 / 头部公司 → 判断风口期或收缩期
⑥ 确定目标公司 job-negotiation-strategist 第四步 必做
先问：是否已有想好的公司？
✅ 有 → 记录目标公司
直接进入下一步尽调
🔍 无 → AI 按简历+行业趋势全网推荐（job-recommender）
目标至少 30 个（30 保底可超）：达标池+备选池两层，逐条标注硬条件；合计<30 执行 2-3 次补搜（换关键词/渠道），补搜到优质岗可超 30，仍不足才如实标注缺口并保存记录。社招按工作年限/在职离职/期望涨幅/背调搜
⑦ 公司尽调 company-due-diligence 第0步：确认身份 → 第0步附：确认数据获取方式
先问：是否有企查查/天眼查等付费 API Key？
✅ 有 API Key → 付费 API 调用
获取精确参保人数、完整司法案件、欠税、经营异常等结构化数据
🆓 无 → 默认免费版
通用搜索公开渠道（企查查/天眼查/企业信用信息公示系统/执行信息公开网）
工商基础信息经营与司法风险业务模式与客户员工口碑→ 风险评级 🔴🟡🟢
⑧ 优势 × 劣势匹配 job-negotiation-strategist 第六步
你的优势 → 解决公司的什么问题 → 值多少钱（结合行业薪资定价）；社招按跳槽涨幅15-30%定价
⑨ 生成谈判筹码清单 job-negotiation-strategist 第七步
🔴 硬筹码（急缺/稀缺技能/立即到岗）· 🟡 软筹码（项目/竞赛/学历）· ⚫ 补偿筹码（签字费/绩效保底/调薪点）；社招含薪资流水/offer比较/竞业/职级筹码
⑩ 生成定制话术 job-negotiation-strategist 第八步
表达意愿 + 展示价值 + 提出要求 + 留有余地；含应对压价/画饼/底薪不动时的话术（社招版含涨幅/在职离职口径）
📋 输出：谈判分析报告 交付物
核心优势 + 公司劣势/压力点 + 筹码清单 + 谈判策略 + 定制话术 + 红线 + 最终建议
🗂️ 归档：记忆库 memory-manager
报告 → memory/analysis-archive/（按日期-类型-对象命名）；提炼个人事实 → profile / current-state / career-timeline
🌙 入职后闭环（找到工作之后到下次跳槽）在职阶段
主链路交付的不是终点——入职后进入下面这条在职线，与谈判主线通过「补偿/跳槽」接口相连
⑪ 入职后在岗管理 onjob-management 第0步：确认身份 → 第0步附：确认当前处境
试用期 30/60/90 天目标 → 融入与 visibility（对齐预期 / 找关键人 / 主动暴露风险 / 留痕）→ 绩效博弈
公司恶化信号：欠薪/裁员/画饼不兑现/高管换血岗位信号：被架空/会议不带我/长期杂活/绩效低分无改进路径
📌 监测到 ≥2 个预警 → 自动联动 job-switch-decision，不等被动发生
⑫ 主动跳槽决策 job-switch-decision 该不该走
信号判断（该走 vs 可再等）→ 时机窗口（金三银四/金九银十、拿年终或背书后）→ 在职骑驴找马优于裸辞 → 八步落地：简历→找→面试→定offer→提离→交接→离职证明→社保衔接→背调→竞业核实 → 跳槽理由口径（简历/面试/背调一致）
⑬ 被动离职分支 severance-calculator
被辞退/劝退/被迫离职 → 算 N / N+1 / 2N、判断公司说法合法性、证据清单、仲裁流程（主动走 vs 被赶走，拿的钱完全不同）
🔧 元维护 skill-upgrade-maintainer 对技能包自身
加载全景 + 结构自检（首行是否 ---、有无悬空编号引用）→ 审视意图（需用户确认）→ 知识库时效/完整/缺口体检（联网核实）→ 查漏补缺 → 优化 skill 提示词 → 增加实用步骤 → 同步 README／索引／流程图
